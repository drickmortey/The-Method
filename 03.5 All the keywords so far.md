## *This is a summary of what we've covered up until this point*
> If you don't get what a word means, previous articles cover them. I'm assuming you've read the ones before while writing this course.

# `local`
Adding this behind a variable declaration makes that variable local. About 10% faster than a non-local (global) variable. Syntax: `local identifier = literal`. Usage with the `function` keyword hasn't been talked about yet.

# `const`
Alternate version of `local`, adds a compile-time rule such that the declared variable cannot be overwritten. Not faster than locals. Is exactly the same as `local` in every other way.

# `do`
Starts a code block. Every code block has its own scope. All code blocks need an *end* to them, they cannot continue forever. Code blocks may have more blocks within them.

# `end`
Does what the name implies. Ends a code block. Every code block needs an end to it. Other keywords than `do` create code blocks too, so watch out. IDEs like the script editor will automatically insert these when you press enter.

# Extra: Weird keywords that might haunt you
Sadly, some things that light up aren't keywords in their *strict definition* (see article 02). One example that sticks out is `self`, it's actually just a local variable. So this is possible..
```lua
self = 5187593 --Great, we have made "self" pointless now

--we can even make a new variable called "self"

local self = "yada yada"

--or if self already exists, this can happen too

local self = self
 --[[looks stupid (it is), but this allows a cheesy workaround in the type system.
 This is (part of) the trick I was talking about.]]
```

Poor `self` isn't alone on this. `type` is another confusing little thing that's hard to describe. Sometimes it's a function, other times it's a "keyword"? I mean yeah in that second case it does meet the criteria of what makes a keyword. It's like a hybrid thingy.

Here, look:

```lua
--[["type" only has the keyword shenanigan going on in Luau,
 it's a regular degular function in Lua. So it will light up as a function here,
  try it at Luau Playground.]]

--let's create a type definition using the KEYWORD
type Car = {Moss:number, MossGrowing:boolean, Tires: "None"|"Please fly"}

--let's use it
local NewVehicle: Car = {Moss = 500, MossGrowing = true, Tires = "Please fly"}

print(
    type(NewVehicle) --here it is as a FUNCTION??
)
```
This tomfoolery extends to its brother `typeof` too. Don't ask what's the difference, you'll confuse yourself even more.

There's `continue`, looks and feels like a keyword. That's debated for some reason. It's one of Luau's notable additions over Lua. While Lua users were nagging the team behind it to add a `continue` keyword, they argued it wasn't really a keyword, but "syntactic sugar". This means that something is essentially shorthand (or an easier way to write) something else that's longer. Notable syntactic sugar in the language is the colon `:` notation and `self`. Basically, they were saying since it's syntactic sugar, they can write another structure on top to get the behaviour they want. 

Try this:

```lua
--"continue" is used in a loop
local list = {"Aananas", "Bapple", "Arrange"}
for i, v in list do
(function()
--[[suppose we don't want to print the second item in the list.
 we want to "continue" the loop forward instead of printing it.
But woah we don't have that???]]

if i == 2 then
    return
end

print(v)

    end)()
end
```
It looks like a hacky workaround doesn't it? Compare that to this:
```lua
--"continue" is used in a loop
local list = {"Aananas", "Bapple", "Arrange"}
for i, v in list do

--[[This looks cleaner and is shorter

    "continue" won't light up because it
    doesn't exist in Lua.]]

if i == 2 then
    continue
end

print(v)

end
```

Comparing the bytecode, using `continue` is *faster*. No reason to not use it in this case.

You may think the Lua team is just being mean and nitpicky. But I think they have a point, Lua has the `goto` keyword that Luau has removed (particularly due to the horrific coding practices it can create). Your program could become death itself when trying to analyze it if your usage of `goto` wasn't sincere and reasonable. It is powerful and there are people advocating for it, but for Luau it was a no-go. `goto` allowed you to **skip over** code and *continue* from a different execution point.

Here's what continue **actually** looks like, internally it uses the same goto chicanery.

```lua
-- THIS CODE ONLY WORKS IN LUA
list = {"Sensible", "Names", "At last"}
for i, v in list do
    --same here, let's not print the second entry in the list

    if i == 2 then
    goto TheRealContinue
    end

    print(v)

    ::TheRealContinue:: 
    --will skip execution to the line above
    -- if the goto part runs.

    --This is identical to that "continue" example!
end
```

So the people nagging for `continue` could just do this (skip over to the end of the loop). Syntactic sugars like `self` have a stronger reason to exist. Though `goto` is not present in Luau for us to use this simple setup, and so having `continue` in the language was necessary to stop damaging code performance trying to get this basic mechanism. It's easier to type "continue" too instead of setting up a `goto`, hauling over to the end of the loop to write "skip to here".
> If you noticed, in the introduction I said "Code from 15 years ago will work in this new language (Luau)". So how if `goto` isn't in Luau? `goto` was first introduced in Lua 5.2, while Luau is designed to be backwards-compatible with Lua 5.1. 

`goto` looks powerful and you might want it in Luau.. you haven't faced the errors it can cause, have you?

Alright we have established that `continue` is NOT a keyword, but rather syntactic sugar (for a keyword that Luau has removed). You can see exactly what it does up there. So `continue` in reality, is a statement alone. Notice that simply typing "continue" (where applicable) works. This means it's a standalone statement. The compilation error for using it incorrectly also says, "*continue statement must be inside a loop*".

A lot of people don't know this extra knowledge. You can now safely correct somebody when they use the term "keyword" incorrectly.
