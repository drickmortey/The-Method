# Comments in Luau

Notice the text I use when explaining and documenting code examples?

```lua
local x --Wow such riveting code
```
These are comments. Comments are "dead code", they're completely ignored and removed before compiling the source into bytecode. You can define a single-line comment with `--`, everything after it will be commented on that line. Comments exist to explain code. Create well-documented code, because stuff can get ambiguous and uncertain quick.
```lua
--Use meaningful names!
--Don't have the "just make it work" mentality.
--Longer names won't end you!
local b = 5
local h = 2

local A = (b*h)/2 
```
What the code is doing isn't complicated at all. But we don't know why we need `A`, or why that specific sequence of operations produces what we need, or what `A` even is. We do not know what `b` and `h` are either, they could stand for anything as far as you're concerned. `5` and `2` are easy to understand, their purpose isn't. We aren't told what its purpose is and what it represents. Your code is terrible if these cases aren't **documented** (properly explained). Trash well-documented code that's easier to maintain is better than optimized code that has nothing explaining anything.
> Good identifiers (names) are just as important as good comments. Your identifiers should tell you what a variable is and what it could be for, bonus points if you use naming conventions to convey extra meaning. E.g. PascalCase for API, `HelloApi` (don't capitalize acronyms), camelCase for functions, `toCelsius`, and all caps for constants, `MAX_PLAYERS` (separated by underscores). Naming conventions should have their own mini-article.

> Identifiers shouldn't be sentences. Comments should be. Keep it compact.

The philosophy above is kind of harsh, I believe it only really applies to **non-trivial** code. What we've been writing is called **trivial** code, code that isn't going to be used anywhere. Think about it, a program "`local y = 10`" isn't realistically going to be present in a game. It creates a container and does nothing useful with it, but we're learning. Non-trivial code is the one that we use in production-level systems, code that will be present inside a game. I believe what I said applies to non-trivial code. Still nice to add comments when learning.

```lua
--Single line comment
Stops commenting after a line break

--[[Oops!

That second part isn't commented! I should have used a multiple line comment there..

Speaking of, you can create a multi-line comment with -- followed by two pairs of square brackets, which will end the comment after the first occurrence of ]]. Wait, I accidentally ended the comment!! 
]] 

--To address this issue, Lua and Luau have this:

--[=[
Great, I can now say ]] as much as I want.
The markdown code block might say otherwise, but try it in Luau Playground.
]=] --Notice how it only ends after the first occurrence of ]=], depending on however much equals signs the opening brackets have.
```
```lua
--Comments are pretty useful here too, if you want to comment out a specific piece.

local --[[x]] y = 5 --I can't decide on the name, I'll keep the old one there for future consideration.
```
