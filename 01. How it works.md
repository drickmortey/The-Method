# What is scripting, really?
<p>
Scripting IS programming, but a special kind at it. 

It's the process of controlling another program via "scripts", this program in our case being the Roblox engine. Think about it, the Roblox engine has 3D graphics, online multiplayer, physics, it's a huge thing. With only Luau and no engine, we're practically in a void. We can't do anything useful other than use the limited stuff that Luau itself comes with. We need the Roblox engine to extend our functionality.

E.g. Luau doesn't really have a way to create a part in the world, we must use what control Luau gets of the engine to do that. This is called **Engine API**, you can view the entire list of what's included right here at https://create.roblox.com/docs/reference/engine. Seriously it's a gimongous list.

> API stands for Application Programming Interface, it's a way that something with more control gives us access to it for a particular purpose.
</p>

# Why Roblox chose a scripting language
<p>
You'll sometimes hear people say that scripting languages are ultra slow compared to "programming languages" (they are mainly referring to C or C++), in a nutshell this is true, but that's not the whole story. So why a scripting language?

Let's not discredit Luau, it's pretty fast. It's also just what Roblox needs, its implementation as a scripting language makes it so that it isn't the boss around the place. It needs another program to control, what that program is written in is called the **Host language**. Roblox in particular, C++ hosts Luau. 

### So why not let me use C++ if it's so good???

1. It gives the programmer too much control, Roblox games are supposed to come malware-free and threat-free.. Other than that, you can do really stupid things. One of its design principles is to let the programmer do *whatever* they want. This is not what Roblox wants!

2. It's simply a very complicated language. Its bar of entry basically excludes children.

3. There's a lot of things in the engine that you have no business in. You decide what a scripting language sees, its abilities mostly constrained to what API you expose to it.

4. Many scripting languages (especially Luau) have simplified programming and have hidden the complexities so you don't shoot yourself in the foot. You don't have to think about freeing memory, not adding things into arrays past their size, or which of the 4 or 5 ways you should initialize your variable (I can't even remember).

> Luau is a high-level language, this doesn't mean it's hard to understand. This means it's far from hardware with the amount of simplifications (or in technical terms, "abstractions") that it has. You don't have to face many weird computer gimmicks. C++ is considered middle-level, though by today's standards some call it low-level (not true but alright). Assembly is undoubtedly low-level, and the closest to hardware is machine code (binary).

## And the main reason!

5. Running your code is actually not that expensive. The rest of the engine utilizes the power of C++, which does the bulk of the work (e.g. updating physics 240 times a second). Code performance usually isn't a big deal, the bigger concern is what your program causes for the engine (creating 1000 parts in a second is "easy" to execute, but?). 

### What if I really need the performance?

Sometimes yeah, you could use more metal. Your code will only run on a single CPU core, which is rarely a problem (this is a deliberate design choice, trust). Roblox has provided Parallel Luau to utilize more cores if you need, along with other tools. If you're optimizing for mobile, the physical world is usually the kidney stone because unoptimized builds can hog up RAM and choke the small little graphics card. *This doesn't give you a pass to write abhorrent code by the way*.
</p>
